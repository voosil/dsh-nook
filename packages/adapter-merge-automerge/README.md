# 自动合并 Adapter

本包封装固定版本 `@automerge/automerge@3.4.1`，算法标识为 `nook-automerge-1/3.4.1`。产品行为、保存接口及历史恢复见[同步契约](../feature-sync/README.md#自动合并与笔记历史)。

## 版本重放

现有记录快照和父版本图是事实来源，不修改远端格式。每条记录通过固定 Actor 和 `time: 0` 初始化共享空文本及字段映射，各快照使用其版本 hash 派生的 Actor，合并父状态后生成与快照的差异。Markdown 和项目描述通过 `updateText` 转成文本操作；其他业务字段编码为不可变 JSON 字符串。ID 和时间不参与字段竞争，删除与编辑并发采用可见状态。

版本遍历、父顺序和字段写入顺序固定；合并版本引用全部当前头，更新时间取输入最大时间，只用于展示。创建时间取输入最小字符串值。文本超限时取排序最前输入头的对应字段，附件并集超过协议容量时取该头的附件。未知 schema 不参与重放。

同一内容的 Automerge `save` 字节可能随内部排列不同而变化，因此这些字节仅是本机缓存，不参与同步版本 hash。相同输入的业务快照及排序父版本通过现有 canonical JSON 生成相同的远端身份。依赖或转换规则变更必须更新算法标识并重新验证历史重放与跨设备收敛。

## 生命周期与缓存

每个 Notebook 按需创建一个 Worker，CPU 密集的文本转换不在 Host 主线程执行。Worker 缓存最近参与合并的头状态，序列化缓存总量不超过 64 MB；重启、取消或卸载后按版本历史重建，不依赖缓存恢复业务数据。缓存容量不是整个 Worker 的内存上限，重放成本与正文及历史规模有关。

调用只传递 Nook 的 JSON-safe 版本 DTO；Automerge 文档不越过 Adapter 边界。取消请求终止 Worker 及其正在计算的批次，其他调用自动排入新 Worker，原始版本保留供重试；Notebook 卸载终止 Worker 并撤销监听。普通单分支保存不触发 CRDT 重放。

`updateText` 是上游实验性接口，限于本 Adapter，使用固定依赖和[收敛测试](../../tests/integration/sync/auto-merge.test.ts)约束。文本操作从保存快照推导，合并结果可能不符合原始编辑意图；原始版本永久保留用于恢复。
