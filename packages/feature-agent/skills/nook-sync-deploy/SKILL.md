# Nook 同步配置

本指南随 Nook 的同步配置提示词提供，附有固定版本助手 URL、SHA-256 和交互安装命令。内置 AI 也可调用可用的 `nook_sync_deployment_guide` 获取同版本指南。缺少安装信息时先从目标 Nook 的“数据同步 → 配置 → 配置指南”复制完整提示词，不猜测下载地址或校验值。

## 需求与状态识别

先根据用户的表述确定本次是连接已有服务、部署新服务还是排查故障。用户已说明目标时直接进入对应路径；需求不明确时先简短询问，不通过扫描环境推断用户意图。确定路径后，只获取下一步所需的信息。

内置 `nook_sync_status` 只代表提供该工具的 Nook Host。同步禁用或地址为空表示该 Host 尚未接入，不能据此判断用户没有服务器。没有工具时，引导用户在目标 Nook 的“数据同步”查看状态，只反馈地址、状态和脱敏错误。

按需求选择路径：已有服务需要接入设备，进入“连接已有服务”；需要新服务，进入“部署新服务”；现有同步异常，进入“故障排查”。已确定范围内连续推进，已有授权不重复询问。需要远程访问时才补充连接方式；账号登录、系统提权或宿主明确要求审批时由用户参与。仅部署服务的任务以服务器验收结束，设备接入和多设备同步按本次范围执行。

## 连接已有服务

先取得已有服务的地址或私有连接文件路径，以及目标设备；缺少时直接询问用户。按已知连接方式检查接入条件，不普查 Docker、SSH、历史主机或部署痕迹。WebDAV 需要 HTTPS、Basic 认证、强 ETag 和原子条件创建、更新；兼容性以目标 Nook 的“验证并开启同步”结果为准，不绕过校验。已绑定的地址及远端库不能直接更换；目标不匹配时先核实，不清空本地库或重置远端索引。

有部署工具导出的私有连接文件且可操作目标 Host 时，按“私密连接交接”和“Host 内部导入”执行。其他情况引导用户在目标 Nook 的“数据同步 → 配置”导入连接文件、粘贴连接信息，或填写地址和凭据，再点击“验证并开启同步”。凭据只填入目标 Nook，不经 AI 对话交接。每台目标设备分别验证；Tailscale 部署需要该设备的 Nook Host 加入同一网络。

## 部署新服务

以下流程适用于随附的 Nook 安装助手。先核实环境是否在助手支持范围内；不支持时回到 Nook 的“数据同步 → 配置 → 配置指南”选择部署方式，不强行运行助手。具备终端及权限的 AI 执行操作；否则给出当前步骤的命令，由用户在对应机器执行并反馈脱敏结果，再继续。

### 环境预检

检查部署目标的系统、sudo、磁盘、现有容器、Nook 回执和网络。通过 SSH 访问时复用已有配置，仅补充未知的 SSH 别名或地址，不索取聊天中的密码或私钥。只支持助手声明的 Ubuntu/Debian、systemd 和 amd64/arm64；不卸载其他容器运行时。

### 可信安装

使用本指南固定的 HTTPS URL 下载助手到管理员专用目录，并比对随附的助手 SHA-256；成功后以 root 运行 python3 assistant.py install --yes。助手会逐层验证归档和镜像。由用户执行时使用随附交互安装命令。

### 服务器登录与验收

安装输出包含 NOOK-SYNC-1 凭据，完整日志必须私密保存，对话输出过滤该行。Tailscale 登录链接只交给用户，并等待 status --json 的 BackendState=Running；不要把等待超时当作授权。已有有效登录复用。服务器完成后检查目标绑定、健康、systemd 和备份。不要默认重启承载其他业务的整机。

### Tailscale 设备接入

需要接入此服务的目标 Nook Host 须安装 Tailscale 并加入同一网络；已有安装和有效登录复用。按目标系统的官方安装方式配置，提权和账号授权由用户在系统页面完成。

## 私密连接交接

已有私有连接文件时直接用于导入。需要从 Nook 安装助手导出且有相应终端权限时，在确认的源服务器执行 docker exec nook-sync-assistant-sync-1 python3 container.py export，将输出直接保存成目标 Host 上的私有 connection.json；不要让模型读取文件内容。文件限制为当前用户可读，不进入对话、日志或版本库。遵守宿主的敏感文件传输审批，说明源、目的地及所含凭据。

## Host 内部导入

已获准接入目标 Host，且该 Host 提供导入工具时，得到独立核实的完整 HTTPS URL 后调用 nook_sync_import_connection(file=<本机绝对路径>, expected_url=<服务器同步目录>)。工具内部读取凭据，复用正常 Host 备份、TLS、认证和原子写入验证。不要直接改 settings.json，不要把密码放进 Tool 参数、提示词或日志。工具只操作提供它的 Nook Host。目标设备不同或没有该工具时，使用目标 Nook 的手动导入入口；不能误用浏览器电脑路径。

## 故障排查

根据目标设备的同步状态与实际错误检查相关环节，保留双方数据、凭据和备份，修复后重新验证。目标索引缺失、库被替换或历史回退时停止同步并核查目标与恢复记录，不清库重下、不手工重建索引。仅排查问题时不自动重新部署服务。

## 按范围验收

服务器部署检查目标绑定、服务健康、systemd 和备份，单独报告。设备接入需通过目标 Nook 的连接验证；导入文件或服务器安装成功不等于完成同步。

需验证同步时，在目标 Host 调用可用的 nook_sync_run 和 nook_sync_status；只有 enabled=true、lastSync 非空、error=null、pending=0 才报告该 Host 本次同步完成，并单独报告冲突及 unsupported。没有工具时，引导用户点击“立即同步”并确认“已同步”和错误状态。无法检查的设备标为未验证。

多设备同步还需在一台设备新建测试笔记，完成同步后在另一台设备同步并确认内容可见；单台 Host 对账成功不代表其他设备已经接收。保留测试笔记供用户检查。

## 交付

按本次范围回报各目标设备接入和实际同步结果、连接地址、已创建的备份位置及仍需用户处理的事项。部署任务另行报告服务器验收结果，未验证的事项如实标明。
