# Nook 数据同步

同步运行于每台设备的本地 Host，依赖 Nook Sync Capability。服务器实现与验证边界见[部署工具契约](../../scripts/sync-server/README.md)。

## 范围与状态

[任务及提炼记录](../provider-task-sync/src/index.ts)通过通用副本同步。笔记和项目参与同步，包含正文、标题、置顶、时间、回收站、来源和项目归属。AI／视频内容保存为笔记后按同一规则处理。SQLite 文件、FTS 和切片不上传，接收笔记时在本机更新索引。独立产物、原始音视频、DSH 对话、模型配置、知识会话偏好、浏览器草稿与本地备份不上传。Markdown 外链保持原值，本机路径不会转换为可跨设备访问的附件。

编辑器的“已保存到本地 · 已入库”表示本地事务完成；侧栏另行显示等待、进行中、失败及完成状态。“已同步”表示最近一次远端对账完成且当前无待发版本，不表示其他设备已经接收。离线修改保留在 SQLite，关闭同步不清除待发版本或本地内容。

本地变更约 1 秒去抖后尝试同步；启动及手动操作可立即触发，正常运行每 5 秒检查，轮次完成后仍有待发版本时约 1 秒再检查。失败按指数退避并加入随机延迟，上限约 6 分钟。每个 Host 串行运行同步；关闭或卸载会取消请求和定时器。同机网页和桌面复用[共享 Host](../../docs/runtime.md)。工作区每 3 秒检查本机变化，刷新列表和未编辑的正文；有未保存输入时按编辑基线自动保存并合并，保存期间继续输入沿自己的分支提交。

## 自动合并与笔记历史

版本以父版本关系判断先后，不比较设备时钟。笔记和项目的并发分支自动合并，不展示人工冲突处理入口，不自动产生副本。正文和项目描述使用文本 CRDT，其他业务字段使用确定性寄存器；原始分支和合并结果均保留。合并后的文字可能包含双方在同一位置输入的内容；超出字段容量时，该字段确定性采用一个输入版本，完整输入仍在历史中。[合并 Adapter](../adapter-merge-automerge/README.md)定义重放、缓存和结果身份规则。

笔记删除使用回收站标记。同一记录删除与编辑并发时保留编辑，之后基于合并结果再次删除正常生效。项目、笔记及同步元数据共用本地 SQLite 事务。项目删除保留正文并解除归属；远端项目删除与离线新增笔记相遇时，本机把不存在项目下的笔记归入未分类，并停用该项目的知识会话。原归属保留在版本及恢复记录中，不把跨记录关系推断为一个合并组。

编辑器和回收站笔记提供“历史版本”，按子版本先于祖先的顺序分页读取版本。界面将相邻保存间隔不足 5 分钟的连续单分支编辑聚合为阶段，默认展示阶段的最后一次保存，展开可选择每次保存，比较原始 Markdown 与当前内容的差异。创建、分支交汇点、自动合并、删除和可识别的恢复独立展示；时间倒退或无效时不聚合。分页每次默认读取 50 个原始版本，加载更早版本后补全阶段及保存次数，不隐藏或删除底层快照。

恢复生成新版本，不回滚或删除后续历史；也可主动另存为新笔记。恢复后的笔记可见，缺失项目归属为未分类。历史随版本链同步，已下载历史离线可读，关闭同步仍保留本地版本；未提交的浏览器输入仅属于草稿。历史恢复在同一事务追加 `note-checkpoint` schema 1 记录，记录 ID 为恢复结果的版本 hash，数据为 `{ noteId, versionId, kind: 'restore' }`，无父版本、删除标记及附件；该记录随通用同步传递，仅用于历史展示，不参与笔记合并。回收站恢复由父版本的删除状态识别；缺少标记的既有历史恢复不推断操作类型。旧客户端把新标记类型作为未知类型保留转送，并可能提示升级。每次历史恢复额外占用一条同步索引记录，遵循通用容量限制。

编辑器在每次输入时保留浏览器草稿，停止输入 3 秒后提交版本，持续输入最长约 30 秒提交一次；输入法组字期间暂停提交，确认文字后沿用同一调度。切换笔记、打开历史及主动保存立即提交。自动提交期间继续输入会合并到下一次调度，主动保存则等待队列排空。与编辑基线完全相同的保存不生成新版本，也不更新时间；历史恢复仍生成独立恢复版本。

保存请求包含编辑基线 `versionId` 和幂等 `requestId`，返回 `{ note, submittedVersionId }`。保存期间继续输入时使用已提交输入的版本继续编辑，队列清空后应用合并结果。草稿保存基线和待确认请求，重试复用请求标识；旧草稿缺少基线时以当前版本保存，被替换内容保留在历史。没有基线的旧接口调用仍检查本机 revision。历史恢复和另存也使用幂等请求标识。

启用前创建并校验完整业务数据备份；远端替换、删除、解除归属、分支保存、自动合并及历史恢复前写入并校验恢复记录，失败则回滚该落地事务。已经成功保存的原始分支不因后续合并失败消失。备份位置和恢复操作由[备份指南](../../docs/backup.md)定义。备份与远端历史不自动清理。

本机首次连接后绑定目标地址及远端库 ID。目标索引消失、库 ID 改变、索引代数回退或已见历史缺失时停止同步，不清库重下。切换目录需要独立本地库；仅修改同一目标的凭据可以重新验证。恢复较早的本地完整备份后可继续与同一远端对账，离线分支参与自动合并。旧远端对象无需重写；所有设备升级后享有完整自动合并体验。不要手工编辑远端协议文件。

## WebDAV 要求

远端必须支持 MKCOL、GET、PUT、DELETE、强 ETag、原子 `If-None-Match: *` 创建和原子 `If-Match` 更新，并原样保存上传字节。配置验证会创建临时探测对象，测试两个竞争写入者只能有一个成功，再删除探测对象。已有业务对象不会被探测清理。短暂弱 ETag 会重新读取至多 3 次，仍不具备强 ETag 的目标拒绝条件写入。应用不把弱 ETag 转换为强 ETag，也不降级为无条件覆盖。

非本机地址要求 HTTPS；可在“服务器 CA 证书”中填写部署工具生成的公共 CA 证书，该信任仅用于当前同步连接，仍校验主机名、证书链与有效期，不修改系统信任或关闭证书验证。公开可信证书保留此字段为空。认证使用 Basic 用户名和存储密码／令牌，不支持 Digest、交互式 OAuth 或重定向。同步目录的上级目录须预先存在。WebDAV 服务或代理配置更改后应重新验证，有限探测不能证明服务在所有负载下的行为。

[独立服务测试](../../tests/helpers/services/apache-webdav.mjs)使用 macOS Apache 2.4.62、mod_dav_fs、prefork 单工作进程与关闭 KeepAlive 的隔离配置。该测试只监听回环地址；公网部署需自行配置 HTTPS、认证、权限及同等写入串行性。不能从此测试推断多工作进程、NAS 或网盘配置兼容。WsgiDAV 4.3.5 的文件 Provider 在实测中对同一秒内的等长更新复用 ETag，未通过验证，不列为可用目标。其他实际存储服务的兼容性为 UNKNOWN。

## 通用协议与扩展

[Capability](../capability-sync/src/index.ts)定义格式、校验、存储接口及 Host 类型注册；[副本存储](../storage-sync/src/index.ts)拥有版本和事务；[同步引擎](src/engine.ts)只处理通用记录及二进制引用；[WebDAV Adapter](../adapter-sync-webdav/src/index.ts)处理 HTTP；[DSH Adapter](../adapter-sync-dsh/src/index.ts)暴露设置、状态和兼容用的冲突操作，产品界面使用自动合并及笔记历史。业务 Feature 通过 Capability 接入，不依赖 WebDAV 或具体 Provider。

远端布局为 `index.json`、`objects/<sha256>` 与 `blobs/<sha256>`。任务执行归属另存 `authority-task-owner.json`，内容为 `{format: 1, ownerId}`，仅以条件创建写入；归属不轮换、不自动删除，不参与记录合并，备份远端存储时需保留。格式 1 的索引包含库 ID、十进制字符串代数及 `type/id → 当前版本哈希数组`。版本包含类型、稳定记录 ID、类型 schema、父版本、删除标记、JSON 载荷及文件引用；其规范化 JSON 字节的 SHA-256 是稳定版本 ID。文件按原始字节哈希定位，包含字节数和媒体类型的引用随记录传输。

本地保存将业务数据和不可变待发版本一起提交；接收先下载并验证历史和文件，再事务性合并远端基线与业务投影。发布先上传并核验依赖，最后条件替换索引。竞争失败重新读取并合并；响应丢失通过已发布版本的祖先关系确认。确认针对捕获的版本集合，发送中继续编辑不被旧确认清除。没有业务变更时仍读取索引，但不重复下载已有对象。

每轮最多 6 路对象传输；下载按记录并发，有历史清单时按压缩块读取，旧索引按父引用逐对象遍历。上传对象及共享附件按路径去重，所有待发对象完成写入和完整回读校验后才发布索引；同轮索引竞争重试复用已验证对象。任一任务失败或取消时，取消并等待同批请求结束，不接收部分版本批次或发布不完整索引。WebDAV 连接池仅属于一次连接验证或同步轮次，调用方在结束时调用可选的 `SyncStorage.dispose()`；持有连接资源的 Adapter 必须实现清理，私有 CA 信任不跨实例共享。

同步索引的可选 `packs` 字段将当前 head hash 映射到历史清单 hash。清单位于 `objects/<hash>.history`，规范化 JSON 为 `{ format: 1, head, chunks: string[] }`；每个 chunk 位于 `objects/<hash>.pack`，内容为 gzip 压缩的规范化 `VersionItem[]`，文件名校验的是实际传输字节 SHA-256。历史按父版本优先、同层父引用按 hash 排序分块；每块最多 128 个版本，通常不超过 1 MB 未压缩内容，单个大版本独占一块。清单、压缩块和解压输出上限各 8 MB，清单与单条历史最多 100,000 项。稳定的完整前缀块在后续编辑时复用，仅重新发布变化的尾块和清单。

接收端验证清单、压缩字节、解压上限、每个版本的身份及记录归属，再按原有父引用和附件检查完整历史。全部版本落地后，同一事务在本地记录已接收块，后续同步跳过这些块；失败或取消不记录部分批次。发布端在原始对象和历史包验证完成后条件发布索引，复用上轮索引清单已经引用的块。没有待发编辑时也为缺少清单的既有 head 补充历史包；首次补包会有一次性开销。旧客户端忽略可选字段，仍可读取全部原始对象；旧客户端发布的索引可能不包含 `packs`，新版接收后会补回。服务器沿用普通 WebDAV，无需专用批量接口。未变化的远端记录跳过重复的祖先遍历及待发确认，业务投影仍可在新类型注册后补齐。

新增类型通过 `nookSyncReplica.registerType` 注册名称、schema 和同步校验器，用 `records(type)` 读取，用 `writeRecords` 携带期望版本批量写入，注册返回的 disposer 归插件生命周期管理。省略 `apply` 可直接以通用记录作为存储；可选的同步 `apply` 仅用于事务内的本机派生投影，不得提交独立数据库、网络或异步副作用。外部通知通过提交后的订阅发送。二进制先经 `receiveBlob` 验证并持久保存，记录才能引用。可选 `copy` 定义兼容接口的副本语义；可选异步 `merge` 接收完整记录历史和当前头，返回 JSON-safe 的正文、删除标记及文件引用。`reconcile` 在事务外计算，提交前重新核对当前头，过期结果重新计算。未注册合并器的类型及未知 schema 保留分支，不猜测语义。

未知类型或较新的类型 schema 原样保留并继续转送，界面显示升级提示；注册相应处理器后下一轮对账可生成投影。不支持的协议 format 拒绝接收。业务新增字段应升级类型 schema，避免旧处理器丢弃字段。笔记的 `revision` 仍是本机乐观锁，`versionId` 是跨设备内容版本；新生成的来源引用可以带 versionId，旧引用不伪造缺失历史。

索引和单版本对象上限各 4 MB，索引至多 10,000 条记录，每条至多 64 个冲突头或父版本，每个版本至多引用 100 个文件，单文件至多 20 MB，单次历史遍历至多 100,000 个版本。首次同步需要下载可达历史和文件，索引按整体读写；历史包提供传输压缩，不删除底层版本；没有索引分页或垃圾回收，不适合无限增长的数据集。达到限制时停止推进并保留本地数据。

## 数据代次

索引格式 2 增加 UUID `epoch` 和指向 `objects/<sha256>.epoch` 的 `transition`，仍使用原库 ID 和单调递增的 `generation`。迁移对象是 gzip 压缩的规范化 `SyncEpochTransition` JSON，哈希校验实际传输字节，压缩与解压上限各 32 MB。清单保存完整来源索引 `from`、新代次、基线 `heads/packs` 及 `{ id, version, data }` 策略标识和 JSON 元数据；来源索引的迁移引用连接更早代次，每轮最多跨越 64 代。不支持格式 2 的旧写入者停止同步，不能把旧图当作普通编辑写回新基线。

Host 通过 `registerEpochMigration` 注册同步的校验、版本映射和局部重写函数，返回 disposer。远端只选择本地已注册的策略，不传递代码。未知策略拒绝接入，包括首次连接。`publishEpoch` 接收完整计划并验证版本图及附件，上传并校验全部依赖后以来源索引的 ETag 条件发布。客户端通过 `adoptEpoch` 在已验证完整备份之后，将投影重置、旧版本压缩归档、新基线及重写后的待发修改置于同一事务。带 `apply` 的类型处理器必须同时提供事务内 `reset`；跨记录引用通过 `references/remapReferences` 显式定义。普通同步仍禁止代数回退和已见历史消失，只有已注册的代次迁移允许重写基线。

内置 `history-rewrite@1` 使用旧版本到新版本或 `null` 的映射，保留当前记录和必要引用，不让已发布且明确删除的版本成为待发修改。本机未发布分支按策略重写，必要时恢复最小编辑基线；本地压缩归档和回执支持晚到的笔记草稿。笔记保存请求的幂等回执跨代次保留，重试按需映射或恢复原提交版本，避免响应丢失造成重复提交。业务处理器的重置、引用语义及策略重写必须与各自 schema 一致，失败回滚。

历史重写复用[阶段聚合规则](../capability-note/src/history.ts)，保留当前记录及必要引用；未知引用语义保守保留。活动历史、压缩归档、已验证备份与远端旧对象的生命周期不同，代次发布不执行远端垃圾回收。

[代次维护工具](../../scripts/data/sync-epoch.mjs)只接受未被数据锁占用的独立业务副本。`plan` 会同步该副本并可能发布兼容旧协议的历史包，不是只读预览；结果包含候选基线、版本映射、统计和已校验备份。`publish` 核对备份与目标，校验不可变对象后按来源 ETag 切换索引；规划后有并发写入必须重新规划，不能无条件覆盖。发布响应丢失可重试同一计划，回执保存在计划旁的 `.published.json`。工具不替换正式数据库，本地接入仍走有备份保护的事务迁移。恢复旧备份应使用独立目录并重新接入迁移链，不手工回退远端代数；设计与验证依据见[迁移决策](../../.agents/notes/implemented/architecture/2026-09-11-sync-epochs.md)。

## 配置与隐私

同步设置支持导入部署工具生成的 `connection.json`，或粘贴其 JSON 内容及安装助手输出的 `NOOK-SYNC-1:` 前缀 Base64 UTF-8 文本。编码只用于交接，不提供加密；解析允许复制时的换行，解码后复用相同的严格字段校验。当前文件格式为 `format: "nook-sync-connection"`、`version: 1`，包含 `url`、`username`、`password` 和 `caCert` 四个字符串字段；兼容仅含这四个字段的旧版导出。解析器拒绝未知字段、未知版本、超限内容及夹带凭据的 URL，最大文件大小为 32 KB。导入只填充表单，不连接服务器或保存设置；用户核对目标并点击“验证并开启同步”后复用现有 Host 校验、备份与同步流程，实际 CA 解析和 TLS 校验仍在 Host 执行。文件包含明文凭据，不上传为同步数据或记录到日志。

AI 可通过 `nook_sync_import_connection` 提供当前 Host 的绝对文件路径及独立核实的 `expected_url`，直接执行 Host 导入。文件仅在 Host 内部读取；路径必须指向不超过 32 KB 的普通文件，拒绝符号链接和目标不匹配。成功后复用 `configure` 的备份、认证与原子写入验证并开启同步；`nook_sync_run` 执行首次对账，`nook_sync_status` 返回脱敏状态。工具不接收密码参数，也不返回连接文件、密码或 CA；浏览器的手动导入仍先填充表单。部署操作见[随包技能](../feature-agent/skills/nook-sync-deploy/SKILL.md)，发布与验证边界见[工具契约](../../scripts/sync-server/README.md#安装助手约束)。

`prepareDeployment` RPC 在同步配置目录内创建或复用 `sync-deployment` 工作目录并返回其绝对路径，供部署入口注册 DSH 工作区和绑定新会话。它不修改同步连接或用户已有会话，也不把这个目录当作已完成权限检查的凭据目录；AI 仍按 skill 准备私密交接子目录。

[产品 Profile](../app-all/cordis.patch.yml)在 notebook Provider 设置 `projectsFile` 后启用统一存储；旧 projects.json 一次性导入 SQLite 并保留原文件，迁移回执和初始版本在同一事务提交。未设置该选项的独立 Provider 保留原有笔记能力。目录级迁移的限制见[正式运行环境](../../docs/runtime.md#导入仓库中的旧数据)。

同步 Host 配置的 `file` 指向 `DSH_HOME/nook-sync/settings.json`，保存开关、URL、用户名、密码和可选 CA 公共证书，权限为 0600。密码不出现在状态 RPC、同步记录或业务备份中；客户端仅知道是否已有密码，留空保留已有值。该私有文件不在 `nook/` 业务备份范围，恢复后需重新配置。传输有 TLS，存储内容和本地备份没有端到端加密；存储管理员能读取正文。
