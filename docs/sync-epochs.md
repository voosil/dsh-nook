# 同步数据代次迁移

同步库通过数据代次支持历史精简和其他不兼容的数据重写。服务器地址、目录和库 ID 保持一致；发布操作以完整基线切换当前代次，其他设备在正常同步时接入。普通编辑只增加索引代数 `generation`，不改变数据代次 `epoch`。线协议、处理器契约和容量限制见[同步包](../packages/feature-sync/README.md#数据代次)。

## 设备接入

所有设备需要安装支持目标迁移规则的 Nook，然后按平常方式同步，无需删除本地库、重新填写服务器地址或导入笔记。不支持目标代次的客户端停止同步并提示升级。本机未同步的修改会迁移到新基线，继续参与原有的分支合并；多个代次未上线的设备按顺序接入中间基线。没有离线修改的新设备直接下载当前基线。

每次本地切换前先创建并校验完整业务备份和同步恢复记录。业务投影、活动历史、待发修改及迁移回执在同一 SQLite 事务中切换；备份或落地失败保留原代次。界面尚未提交的笔记草稿可按其旧版本基线从本地归档恢复，再提交为新代次的修改。离线编辑依赖已精简的版本时，只补回该编辑必需的基线。

## 历史精简

维护工具采用界面的同一阶段聚合规则挑选折叠版本，保留每个阶段的展示版本、所有当前记录和必要的历史引用。笔记来源、恢复标记和任务的版本引用随重写更新；无法识别引用语义的数据采取保守保留。当前内容保持不变，历史版本 ID 可能因父引用变化而改变。

精简从活动版本表与同步基线中移除选定历史。本地压缩归档、已验证备份和远端旧对象保留用于恢复；这些归档不参与普通历史查询或同步。该操作不承诺立即回收所有磁盘空间，远端垃圾回收不属于代次切换。备份位置和恢复方法见[备份指南](backup.md)。

## 维护发布

先构建并验证支持迁移的应用，在独立目录准备业务数据的一致副本。维护工具拒绝被数据锁占用的目录；不得直接使用运行中的业务目录。连接文件包含凭据，应保持私密。

```bash
node scripts/data/sync-epoch.mjs plan --data <独立业务副本> --connection <settings.json> --output <plan.json> --backups <持久备份目录>
node scripts/data/sync-epoch.mjs publish --plan <plan.json> --connection <settings.json>
```

规划会将独立副本与服务器同步，并可能补充兼容旧协议的历史压缩包；随后生成候选基线、版本映射、精简统计和已校验备份。发布前应核对精简范围及候选记录内容。发布校验备份与目标地址，上传并回读验证不可变对象，最后通过服务器 ETag 条件替换索引。规划后服务器有任何更新时，发布拒绝覆盖，需重新同步并规划。发布响应丢失时，同一计划可以重试，不会重复创建代次。

发布回执保存在计划旁的 `.published.json` 文件中。该工具不直接替换正式本地数据库；正式 Host 按正常同步流程完成有备份保护的迁移。不要手工覆盖索引或回退服务器代数；较旧的本地备份可以恢复到独立目录，并通过同一迁移链重新接入。
