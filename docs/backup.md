# 数据备份与恢复

备份覆盖 Nook 数据目录中的笔记、任务及其执行与提炼记录、回收站、检索索引、知识会话偏好、项目、产物、视频资料、缓存和删除恢复记录。默认数据和备份位置由[正式运行环境](runtime.md#数据位置)定义，网页和桌面使用同一份数据。DSH 对话、凭据、模型配置及浏览器中尚未保存的草稿不在此范围内。自定义 Provider 存储位置时，分别通过 `--source` 指定对应目录。

## 创建与校验

显式退出任务后台，并停止所有正式网页启动命令和桌面应用后，在仓库根目录运行：

```bash
pnpm backup create
pnpm backup verify --from "<备份目录>"
```

创建成功会打印备份目录。共享后端在启动 Host 前也执行完整备份，加入已有后端不重复备份，备份失败则停止启动。首次运行尚无数据目录时不创建快照。开发模式的临时数据生命周期见[运行指南](development.md)。

手动备份可以指定源目录与保存位置，例如备份到另一块磁盘：

```bash
pnpm backup create --output /Volumes/Backup/Nook
```

备份包含版本化清单、创建时间、原因、文件大小和 SHA-256 校验值。文件写入、刷盘、校验完成后才发布备份目录；失败留下的 `.partial-*` 不代表成功备份。SQLite 使用一致性快照包含已提交的 WAL 内容，并检查数据库完整性；不把 WAL 和共享内存文件作为独立恢复文件。来源依据见 [SQLite 文档](https://www.sqlite.org/lang_vacuum.html)。其他文件逐字节复制，备份期间发现源文件变化会报错。备份拒绝符号链接、特殊文件以及相互嵌套的源目录和目标目录。

启动器和手动备份通过数据目录旁的 `.lock` 目录互斥。绕过启动器直接运行的 DSH 进程不受这个锁约束，创建备份前也必须停止。进程崩溃可能留下锁；确认 `owner.json` 中的进程和所有使用该数据的 Host 都已退出后，才能移除锁目录。这只是进程协调信息。

## 恢复

Windows 文件刷盘使用可写句柄，备份目录和迁移回执通过写穿重命名发布；Node 不提供 POSIX 式的 Windows 目录刷盘接口。文件内容和清单仍须逐项校验，发布失败时保留临时目录并中止后续修改。访问权限继承所在用户目录的 Windows ACL，POSIX 模式位只在支持它的平台检查。

恢复先校验全部文件，再写入一个不存在的新目录；即使目标是空目录也拒绝覆盖：

```bash
pnpm backup restore --from "<备份目录>" --to ~/Nook-restored
```

恢复完成后，停止 Nook，为当前数据执行一次完整备份并校验。保留当前数据目录，例如将正式 `harness/nook` 重命名为一个未使用的保留目录，再将恢复出的目录放到原数据位置，随后启动 Nook 检查笔记、项目和产物。不要只替换数据库主文件而遗留旧 WAL 文件。

损坏、缺文件、多文件、不支持的版本或路径越界都会导致恢复失败。写入中断产生的恢复目录保留在原处，重试时使用另一个新目录。SHA-256 用于发现意外损坏，不是对外部备份来源的身份认证。

## 删除保护

[本地存储实现](../packages/storage-backup/src/index.ts)在项目删除、产物删除、笔记进入回收站、解除笔记项目归属前，保存并校验本次操作之前的数据。备份失败不会执行对应的删除或归属更新。

恢复记录位于相应存储路径旁的 `<项目文件>.backups`、`<笔记数据库>.backups` 和 `<产物目录>.backups`。项目记录包含删除前的项目存储，产物记录包含完整元数据和 Base64 字节，笔记记录包含完整笔记 DTO 及受影响的知识会话偏好。记录可用同一校验命令检查；恢复命令将它提取为新目录中的 `record.json`，供选择性找回内容使用，不自动合并到当前数据库。

产品 Profile 的项目与笔记共用 SQLite，项目删除、笔记归属、知识会话偏好及同步版本在同一事务提交。独立旧项目 Provider 仍使用项目 JSON 的单独恢复记录。

同步升级及开启前的完整快照位于业务数据目录旁的 `<业务目录>.sync-backups`；接收、自动合并、历史恢复及通用记录替换的恢复记录位于 `<笔记数据库>.backups`，保留原始版本。数据库快照包含同步历史和待发状态，文件对象位于 `<笔记数据库>.files`，随业务目录备份。私有同步凭据不包含在此目录，恢复后重新配置；同步范围及异常恢复语义见[同步契约](../packages/feature-sync/README.md)。

[同步数据代次迁移](../packages/feature-sync/README.md#数据代次)在切换前执行完整备份并保存同步恢复记录。SQLite 内的 `sync_epoch_archive` 保留旧版本的压缩副本，迁移回执保留版本映射依据；这些数据随数据库完整备份，不属于活动历史，也不参与普通同步。恢复旧备份后，支持对应迁移规则的客户端可以沿远端迁移链重新接入。

备份不会自动轮换或清理。备份与恢复文件使用仅当前用户可访问的权限；它们包含原始内容，没有加密。定期将已校验的备份复制到其他磁盘，并根据实际空间安排保留策略。

## 应用更新备份

[应用更新](runtime.md#运行时切换)在旧后端退出后，为整个 `harness/` 创建已校验快照，覆盖 Nook 数据、DSH 对话、凭据和用户配置。只排除根及各 Profile 中可重建的 `node_modules`、`profiles/node_modules` 和 Profile 的 `.dsh-module-fallback`；这些运行时链接的来源见[发现基线](discovery.md#desktop-launcher-discovery)。其他符号链接或特殊文件导致备份失败并中止切换。文件复制前后逐项比对 SHA-256，再通过本备份库创建和校验快照，SQLite 使用一致性快照。

更新在正式根目录的 `updates/` 保留原始 home，候选版本使用从快照恢复出的目录。失败恢复保留候选目录再恢复原始目录，不覆盖失败版本写入的内容。恢复回执与生效运行时一起发布；下次启动据此完成恢复或选择成功版本。更新快照可用本页的校验和恢复命令提取到新目录，不直接覆盖正在使用的数据。
