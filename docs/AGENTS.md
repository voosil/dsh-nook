# AGENTS.md — 文档标准

仓库文档用于指导 Agent 编码。只保留会改变实现选择、避免已知错误或明确验证边界的信息；不以供人阅读的产品手册为目标。功能现状由源码、类型、配置和测试承载，开发决策与历史从 [.agents/notes/](../.agents/notes/AGENTS.md) 按需检索。操作流程见 [dsh-docs skill](../.agents/skills/dsh-docs/SKILL.md)。

## 分层：一个事实只有一个家

每条需要成文的事实只有一个维护位置，其他地方只链接。写入前先判断是否有必要保留，再决定归属。

| 位置                                      | 收录内容                                               | 不收录                            |
| ----------------------------------------- | ------------------------------------------------------ | --------------------------------- |
| 根 [AGENTS.md](../AGENTS.md)              | 每次编码都需遵守的常设约束，链接到详细规则             | 长流程、已链接文档中的细节        |
| `docs/`                                   | 工程规范、约束、横切机制与核心技术现状                 | 功能介绍、操作导览、功能完成清单  |
| [architecture.md](architecture.md)        | 组合方式、依赖方向、运行时与存储边界                   | 逐功能说明、接口清单              |
| [discovery.md](discovery.md)              | DSH 全局接入依据、共享机制、兼容性与 `UNKNOWN`         | 功能专属接口、上游 API 手册       |
| 包或工具目录的 README（按需）             | 不能从局部代码直接理解的契约、限制、接入陷阱和验证边界 | 搬出 `docs/` 的功能介绍、源码翻译 |
| [Agent Notes](../.agents/notes/AGENTS.md) | 决策理由、真实备选、验证依据与开发历史                 | 重复维护完整功能现状              |

| `.agents/notes/wip/`                      | 尚未定稿的原始想法                                     | 已确认的编码依据                  |

## 收录边界

`docs/` 按技术关注点组织。某功能涉及多个包、具备复杂流程或已经上线，都不是收录理由。横切机制指服务于不同模块的共同约束，例如 Host/Client 边界、数据保护、运行时生命周期；不能把单个功能的跨包调用链当作横切主题。

新增功能默认不新建或扩写 `docs/`。先读相关源码、测试及决策笔记；确有需要长期保留的非显然契约，再写入所属包或工具的已有文档。没有这类信息就不建 README，也不把删去的功能介绍转存到其他目录。历史取舍留在已有决策笔记，不追加功能手册。

`discovery.md` 只保留影响整体启动、组合和共享接入机制的 DSH 事实。局部接入限制与 `UNKNOWN` 跟随所属包，不维护逐功能目录或全仓库未知项清单。版本升级时更新或移除失效结论，历史依据进入决策笔记。

## 写作与校验

- 技术契约写现状，变更理由进决策笔记；不在现状文档维护完成状态或变更日志。
- 链接精确源码、类型、配置或测试，不手抄签名、字段、默认值和可直接检索的清单。
- 一篇文档只回答一个技术问题；删除不影响 Agent 编码判断的介绍、界面路径和重复解释。
- 使用相对 Markdown 链接，保持单文档单语言、段落单物理行（编辑器软换行）。
- 变更后运行 `pnpm docs:check`，检查链接可达性和笔记状态与目录一致性。Markdown 不参与 Prettier 门禁；表格对齐、空白、段落换行和标题模板属于写作建议，不阻塞构建。仍须审查信息价值、归属、重复和过时内容。
