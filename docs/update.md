# 应用更新

源码启动设备可以在“设置 → 应用更新”检查新版本并一键更新。更新作用于当前设备的共享后端，网页与桌面复用同一个版本。桌面安装包自身不由这个功能替换。

## 使用

首次安装更新功能时，拉取代码、安装依赖，退出所有正式入口后运行 `pnpm start`。启动器记录仓库位置、当前分支和 `origin`；可以在启动时通过 `NOOK_UPDATE_REMOTE` 和 `NOOK_UPDATE_BRANCH` 指定其他来源。远端认证使用本机 Git 配置，更新操作不提供交互式登录。没有可用来源时，应用继续运行，更新入口提示从源码启动。

“检查更新”显示目标提交和提交说明。“更新并重启”先保存当前笔记，然后在独立检出目录安装锁定依赖、构建、打包并进行隔离启动检查。准备期间当前版本继续运行；准备成功后自动备份并重启，不等待正在进行的任务。按钮旁明确提示：重启会中止生成、导入和同步任务，完成更新后按需重试。

保存失败不开始更新。关闭设置或笔记工作区不停止 broker 的更新任务；关闭最后一个启动终端或桌面入口会停止它持有的更新进程。切换复用原端口与鉴权配置，笔记工作区检测版本变化后保存当前笔记并刷新。其他浏览器草稿仍由各自浏览器保存，更新不协调多窗口编辑。

## 失败与恢复

构建失败保留运行中的旧版本。切换前执行[完整更新备份](backup.md#应用更新备份)，备份或校验失败不激活新版本。新版本先在随机端口检查，再在原端口启动；验证阶段不运行远端数据同步。启动失败时停止候选后端，保留其数据目录，并恢复切换前目录和旧版本。

源码目录和已有运行时不被覆盖。启动器通过正式根目录内的版本记录选择更新后的快照；普通 `pnpm start` 仍执行仓库构建，但启动已选定的快照。需要使用当前工作区源码时，退出所有入口后运行 `pnpm start -- --source`，下一次普通启动仍按成功更新的版本记录选择快照。

更新日志位于[正式运行环境](runtime.md#数据位置)的 `logs/`，状态记录位于 `updates/status.json`。`runtimes/update-*` 中的 `runtime/` 和 `boot/` 保存独立安装、准备器所用 Node 的独立副本及启动程序；它们与 `candidate.json`、旧版快照、完整备份、切换前目录和失败目录一同保留，不自动回收。

`source/` 是本次更新创建的临时 detached worktree。准备器确认安装路径和依赖链接不指向源码后，通过 Git 移除该 worktree，再在临时数据目录启动候选版本并验证鉴权页面。验证通过才进入正式备份与切换。安装、构建、打包失败或正常取消时，准备器停止子进程后清理本次创建的 worktree。发现源码变更、未知未跟踪文件、依赖仍指向源码或清理失败时，停止准备并保留现场；强制杀进程或断电可能留下残留。自动清理不遍历历史 worktree。

进程中断后的下次启动检查恢复回执；恢复校验失败时停止启动并保留现场。
