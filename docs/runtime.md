# 网页与桌面的正式运行环境

`pnpm start` 通过本机私有连接复用一个 DSH 后端，支持 macOS arm64 和 Windows x64。macOS 的打包桌面应用与它共用正式数据；Windows 使用源码仓库启动网页。`pnpm dev` 和 `pnpm desktop:dev` 使用各自的[隔离开发数据](development.md)，不参与正式数据共享。

## 数据位置

macOS 正式根目录是 `~/Library/Application Support/Nook`；Windows 是 `%APPDATA%\Nook`，未设置 `APPDATA` 时使用用户目录下的 `AppData\Roaming\Nook`。两者均不依赖源码仓库的位置。

| 相对正式根目录的路径           | 内容                                              |
| ------------------------------ | ------------------------------------------------- |
| `harness/nook/notebook.sqlite` | 项目、笔记、任务、检索索引、会话偏好及同步版本    |
| `harness/nook/projects.json`   | 一次性导入后保留的旧项目文件                      |
| `harness/nook/` 的其他文件     | 产物、视频资料、缓存与删除恢复记录                |
| `harness/`                     | 共享 DSH home，包括会话、凭据和用户 Profile       |
| `runtimes/`                    | 按内容指纹安装的应用运行时                        |
| `workspace/`                   | 后端默认工作目录                                  |
| `backups/`                     | 已校验的数据快照与迁移回执                        |
| `logs/`                        | 启动器与共享后端日志，磁盘日志中的鉴权 token 脱敏 |

同步设置和多设备行为见[同步契约](../packages/feature-sync/README.md)。

数据同步弹窗通过入口打开独立的 `#nook-sync-guide` 指南页。Linux 服务器的三种部署模式、配置工具及证书维护见[服务器配置说明](../scripts/sync-server/README.md)。

正式笔记保存在后端 SQLite 中。网页和桌面的 cookie、页面状态以及尚未保存的编辑草稿仍属于各自的浏览器环境。工作区自动检查后端变化，未保存的草稿按编辑基线保存并自动合并，同时编辑及历史恢复遵循[同步契约](../packages/feature-sync/README.md#自动合并与笔记历史)。

## 启动与退出

在源码仓库运行 `pnpm start`，打开终端打印的完整鉴权 URL；桌面直接打开构建出的 `.app`。先启动的入口准备固定的运行时快照并启动后端，后启动的入口复用它。网页首次启动的默认端口为 3081，桌面首次启动使用随机端口；已有后端的端口优先，`-- --port 4000` 只影响新建的后端。

Windows 默认启动探测到 3081 被占用或拒绝绑定时，会自动让系统分配空闲端口，并提示打开终端打印的 URL。显式指定的端口不可用时仍报错，可改用 `pnpm start -- --port 0`。自动选择的端口在下次启动时可能不同，需要重新打开完整鉴权 URL。

每个 `pnpm start` 终端和桌面应用各持有一条连接。关闭桌面时，只要网页启动命令仍在运行，后端就继续服务；停止网页命令时，打开的桌面也能继续使用。最后一个入口退出后，若指定任务主机启用保持后台运行，后端继续服务；否则后端、监督进程与其拥有的子进程退出。桌面显式退出应用会停止保留的后台；任务设置关闭保持后台运行后，无前端连接的后台退出。浏览器标签页本身不持有后端生命周期，网页使用期间应保留启动终端。

共享后端使用正在运行的固定版本。[应用内更新](update.md)统一切换共享后端；手动应用源码构建或配置变更时，退出所有正式入口再重新启动。“窗口 → 重新连接本地服务”重新建立桌面连接，不中断其他入口的服务。依赖安装与完整性检查发生在创建后端时，加入已有后端不重复安装。

Windows 源码启动要求安装符合[根 manifest](../package.json)的 Node 和 Corepack/pnpm，以及依赖安装所需的原生编译工具。创建后端时，所有 Nook 包先打包，再连同固定版本的 DSH 依赖安装到 `runtimes/web-*`；安装位置保持不变，保留 Windows 目录链接。运行时使用启动命令的 Node，监督脚本随快照保存。旧快照不会自动删除。这个流程不生成 Windows 桌面安装包。

Windows 使用命名管道连接共享后端，并通过 Job Object 管理 DSH 进程树。正常退出先触发 DSH 的清理流程，再回收残余子进程；监督进程崩溃时，系统回收该 Job 下的进程。启动期间按 Ctrl+C 也会终止该启动命令拥有的构建或依赖安装进程。

## 导入仓库中的旧数据

`pnpm start` 检查本仓库的 `.dsh-dev/nook`。尚无成功迁移回执时，先要求相关旧进程和正式后端退出，再对源目录与正式数据目录加锁，创建和校验备份，在临时目录合并后发布。旧网页目录保留；被替换的旧桌面目录保留为 `harness/nook.before-merge-*`。再次启动通过迁移回执避免重复导入旧内容。

迁移保留笔记的 ID、时间、revision、正文、回收站状态和索引，项目按 ID 合并，其他文件保留原始字节。相同 ID 的记录相同时去重，内容不同时停止；同路径不同内容的文件也会停止。此时双方原数据、备份和临时合并目录均保留，解决冲突前不会发布合并结果。

完整且无冲突的同步库可以原样搬迁，保留库绑定及历史。目标已初始化同步结构，经结构校验且业务表、索引、会话偏好及同步历史均为空，同步状态仅含已完成的项目初始化标记时，允许以完整源数据库迁入，保留目标目录中的其他文件；旧格式项目在后端启动时按 Provider 的升级流程导入。其余两份不同数据库只要包含同步状态，就拒绝文件级自动合并，保留双方库及已校验备份，需通过数据同步对账。

迁移回执在目录切换前刷盘。中断后，启动器检查待完成回执、备份和目录状态，安全条件满足时继续切换；条件不满足时停止，避免把缺失的目标目录当成空白工作区。

自动导入仅覆盖 Nook 业务数据。旧 `.dsh-dev` 中的 DSH 对话、凭据、模型配置及用户 Profile patch 保留在原处，不与桌面已有配置自动合并。两端之后使用共享 home 中的 DSH 配置；它不等于两个历史 Harness home 的完整迁移。备份覆盖范围和恢复操作见[备份指南](backup.md)。

架构取舍和测试依据见[共享运行环境决策](../.notes/implemented/architecture/2026-09-08-shared-runtime.md)。
