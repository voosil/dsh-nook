# 网页与桌面的正式运行环境

`pnpm start` 与打包的 Nook 桌面应用使用同一份正式数据，并通过本机私有连接复用一个 DSH 后端。该运行环境的交付和验收范围为 macOS arm64。`pnpm dev` 和 `pnpm desktop:dev` 使用各自的临时数据，不参与正式数据共享。

## 数据位置

macOS 正式根目录是 `~/Library/Application Support/Nook`，不依赖源码仓库的位置。

| 相对正式根目录的路径           | 内容                                              |
| ------------------------------ | ------------------------------------------------- |
| `harness/nook/notebook.sqlite` | 笔记、回收站、检索索引和知识会话偏好              |
| `harness/nook/projects.json`   | 项目                                              |
| `harness/nook/` 的其他文件     | 产物、视频资料、缓存与删除恢复记录                |
| `harness/`                     | 共享 DSH home，包括会话、凭据和用户 Profile       |
| `runtimes/`                    | 按内容指纹安装的应用运行时                        |
| `workspace/`                   | 后端默认工作目录                                  |
| `backups/`                     | 已校验的数据快照与迁移回执                        |
| `logs/`                        | 启动器与共享后端日志，磁盘日志中的鉴权 token 脱敏 |

正式笔记保存在后端 SQLite 中。网页和桌面的 cookie、页面状态以及尚未保存的编辑草稿仍属于各自的浏览器环境。对方保存的笔记可在刷新或重新打开工作区后读取；同时编辑同一笔记受现有 revision 冲突检查约束。

## 启动与退出

在源码仓库运行 `pnpm start`，打开终端打印的完整鉴权 URL；桌面直接打开构建出的 `.app`。先启动的入口准备固定的运行时快照并启动后端，后启动的入口复用它。网页首次启动的默认端口为 3081，桌面首次启动使用随机端口；已有后端的端口优先，`-- --port 4000` 只影响新建的后端。

每个 `pnpm start` 终端和桌面应用各持有一条连接。关闭桌面时，只要网页启动命令仍在运行，后端就继续服务；停止网页命令时，打开的桌面也能继续使用。最后一个入口退出后，后端、监督进程与其拥有的子进程退出。浏览器标签页本身不持有后端生命周期，网页使用期间应保留启动终端。

共享后端使用正在运行的固定版本。应用构建或配置更新后，退出所有正式入口再重新启动以应用更新。“窗口 → 重新连接本地服务”重新建立桌面连接，不中断其他入口的服务。依赖安装与完整性检查发生在创建后端时，加入已有后端不重复安装。

## 导入仓库中的旧数据

`pnpm start` 检查本仓库的 `.dsh-dev/nook`。尚无成功迁移回执时，先要求相关旧进程和正式后端退出，再对源目录与正式数据目录加锁，创建和校验备份，在临时目录合并后发布。旧网页目录保留；被替换的旧桌面目录保留为 `harness/nook.before-merge-*`。再次启动通过迁移回执避免重复导入旧内容。

迁移保留笔记的 ID、时间、revision、正文、回收站状态和索引，项目按 ID 合并，其他文件保留原始字节。相同 ID 的记录相同时去重，内容不同时停止；同路径不同内容的文件也会停止。此时双方原数据、备份和临时合并目录均保留，解决冲突前不会发布合并结果。

迁移回执在目录切换前刷盘。中断后，启动器检查待完成回执、备份和目录状态，安全条件满足时继续切换；条件不满足时停止，避免把缺失的目标目录当成空白工作区。

自动导入仅覆盖 Nook 业务数据。旧 `.dsh-dev` 中的 DSH 对话、凭据、模型配置及用户 Profile patch 保留在原处，不与桌面已有配置自动合并。两端之后使用共享 home 中的 DSH 配置；它不等于两个历史 Harness home 的完整迁移。备份覆盖范围和恢复操作见[备份指南](backup.md)。

架构取舍和测试依据见[共享运行环境决策](../.notes/implemented/architecture/2026-09-08-shared-runtime.md)。
