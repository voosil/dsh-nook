# Agent Note: UI 包按文件职责分类组织

Status: implemented

## Problem

UI 包的组件、独立 TS 逻辑和 CSS 混在同一目录，查找文件时缺少清晰分类；大型入口又同时承载插件装配和页面交互。[笔记 UI 入口](../../../../packages/ui-notes/src/client/index.tsx)是本次规范的主要参考对象。

## Decision

以 [UI 包代码组织规范](../../../../docs/ui-packages.md)作为新增与重构代码的依据，由[仓库指令](../../../../AGENTS.md)链接。规范优先按文件职责分类，目录按需创建。`ui-notes` 按此规范组织实现。

`ui-notes` 的组件、独立 TS 逻辑和 CSS 分别归入对应分类目录，入口负责 RPC 和 Slot 装配。根组件、笔记编辑器和富文本编辑器各自拥有实现模块，保存队列及 RPC 解包逻辑保持原有行为。样式由入口随工作区显示状态挂载和卸载，包的公开导出保持稳定。

## Alternatives considered

按业务区域把组件、逻辑和样式放在一起，便于围绕一个业务修改代码，但仍保留用户希望消除的文件混放问题，因此采用按文件职责分类。

为每个组件强制配套 hook、样式和类型文件会产生大量细碎文件，因此只提取具有独立职责的逻辑，类型保留在所属模块。

## Consequences

文件位置可按职责直接判断，小包只创建实际需要的分类目录。跨类型修改可能涉及多个目录，通过一致的业务命名保持对应关系。规范不增加依赖或自动目录检查器，其余包按改动范围渐进整理。

源码目录也使用 `lib` 名称，Git 和格式化忽略规则须允许 Client 源码下的该目录；开发监听器和端到端测试复制器只排除包根目录的构建产物。监听集成测试覆盖 Client 逻辑文件修改触发重建且不重启 Host，并确认构建产物不进入源码快照。

## Validation

格式、文档链接、包边界、类型与构建检查通过。笔记、同步契约及开发监听集成测试共 12 项通过；开发模式端到端测试覆盖 CSS 热更新、构建失败恢复和 Host 重启。Profile 检查通过，独立安装包验收通过 35 个包、25 项 Profile 组成及浏览器笔记流程。浏览器与独立安装验收使用网络和本地进程权限运行，数据限于临时验证环境。
