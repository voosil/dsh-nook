# Agent Note: 提交技能冻结批次

Status: implemented

## Problem

分批提交期间工作区仍可能被用户或其他 Agent 编辑。仅记录待提交文件名无法隔离同文件后续修改;反复读取实时内容还会扩大提交范围,使本轮提交无法结束。

## Decision

由 [commit skill](../../../skills/commit/SKILL.md) 直接规定时间边界:本轮仅提交调用开始时已有的内容,执行期间的新改动等本轮各组提交完成后再询问用户。只有明确同意才进入下一轮,初始范围外的内容不视作期间新改动。

该规则与 [按需取证](2026-09-08-commit-skill-targeted-inspection.md) 配合,不规定额外的 Git 快照协议、辅助脚本或操作说明。用户明确要求简短的行为约束,具体操作由 Agent 根据当前 Git 状态选择。

## Alternatives considered

只冻结路径清单:无法阻止提交同一文件的后续版本,不满足内容冻结要求。

每批重新从实时工作区暂存:会不断扩大本轮边界,也会重复触发取证和分组,因此不采用。

stash 后清空工作区:影响并行编辑,恢复时还可能发生冲突,因此不采用。

完整工作区基线、隔离目录和索引前移:用户明确认为流程过重,因此不采用。

强制 Git tree 与备用索引流程:比完整隔离更短,但仍超出用户所需的简单行为规则,因此不规定此实现。

## Consequences

同一文件的后续编辑也属于下一轮,不能因路径相同就整文件纳入本轮。未获同意的新改动保留,原有部分暂存和仓库验证要求继续适用。

## Verification

校验覆盖技能结构、目标文件格式和文档门禁。此变更是行为指令,不附带快照实现,不将静态校验视为并发编辑场景的模型行为验证。
