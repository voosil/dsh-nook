# Agent Note: 测试按范围集中组织并由统一入口调度

Status: implemented

## Problem

原目录把 contract、e2e、desktop、integration、sync-server 放在同一层，混用了测试范围、子系统和运行环境。verify 同时承载启动辅助函数与大型业务场景，导致启动一个运行时就隐式执行任务和笔记流程；Profile 又在聚合命令中重复执行。逐文件命令与 Python 转调包装让迁移和新增用例容易漏跑。

## Decision

采用本项目的集中式 convention，规范只维护在 [tests 规则](../../../../tests/AGENTS.md)。混合范围的笔记契约、项目契约、桌面策略和启动命令测试拆分；desktop 与 sync-server 作为子系统，独立安装和桌面交付有显式环境组。工程规则保留在 verify，产品断言与环境实现迁入 tests；[验收证据决策](2026-09-12-verification-outcomes.md)的理由保持不变。

[调度器](../../../../scripts/test/run.mjs)递归发现用例，按环境选择已有运行器并传播失败；Python 通过同一语言入口供本地与 CI 调用。聚合只准备一次并去重执行组。源码 Profile、干净安装、Windows 启动、macOS arm64 桌面各有入口，复用具名场景；普通测试不隐式触发特殊环境。

笔记按设置导航、并发合并、历史恢复、项目及笔记生命周期、同步拆分，任务按日历与完成状态拆分。每项场景创建自己的数据；源码场景使用独立 Host，安装与桌面场景复用昂贵安装但不依赖其他测试的记录。自动保存、独立读取、同步接收方、真实恢复和端口重绑定保留为结果证据。安装探针使用目标 Profile 的模块和指定运行时。

Git 对文本统一使用 LF，避免 Windows 检出与代码格式门禁冲突。用户随后明确放宽 Markdown 门禁：Markdown 不参与 Prettier 检查，文档检查只约束链接可达性及笔记状态与目录一致性；排版、固定行号和章节标题作为写作指导，不阻塞验收。同步服务公开命令准备本次源码镜像后再执行真实 Compose 用例；Python 子进程统一 UTF-8，以正确读取跨平台诊断。

## Verification

迁移以实施前工作区副本为基准，包括已有未提交修改；[迁移映射](../../proposed/process/2026-09-12-test-organization-migration.json)随仓库保存，原始快照和日志保留在本地验证产物中。[macOS 接续说明](../../proposed/process/2026-09-12-test-organization-handoff.md)记录阶段验证结果与未完成事项。调度器的集成测试实际执行嵌套用例、重叠组和故意失败用例，检查发现、排除、去重与退出状态。跨环境覆盖分别执行并报告，不能由源码通过推导交付通过。

## Alternatives considered

继续保留 contract、desktop 和 sync-server 顶层目录，会继续混用分类维度。把所有浏览器用例都归入 e2e，无法表达独立挂载组件与完整系统入口的区别。

仅移动文件并保留隐式 smoke，会让启动辅助函数继续携带业务验收，也无法减少重复运行。删除安装环境的重复场景，则会丢失发布内容、原生模块和运行时隔离的独立证据。

引入新测试框架并不能解决归属与生命周期问题，因此保留已有 Node/tsx、浏览器自动化和 Python 工具。

把 Markdown 的换行、表格对齐和模板排版作为构建前置条件，会让无行为影响的差异阻塞产品验收；用户选择保留文档完整性检查、取消排版门禁。

## Consequences

目录、命令、环境与结果报告有明确责任归属；新增嵌套用例无需额外登记。独立前置条件增加源码场景的启动成本，但允许单独定位失败。Python-only 容器无需安装 Node 或项目依赖。未执行的 macOS、Linux 或 Docker 验收仍是验证缺口，不能据此宣称全部平台整改通过。
