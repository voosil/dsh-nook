# Agent Note: 旧网页数据迁入已初始化的空同步库

Status: implemented

## Problem

正式入口初始化数据库时会创建同步表，即使尚无笔记或同步绑定。旧网页目录有数据而正式目录只有初始化标记时，仅凭同步表存在就拒绝迁移，会使 `pnpm start` 无法启动。

## Decision

[迁移实现](../../../../packages/storage-backup/src/migration.ts)分别校验源、目标的已知结构，在同步库合并保护中加入严格的空目标判定。只有业务表、索引、会话偏好及全部同步历史为空，且状态只含已完成的项目初始化标记时，才以完整源快照替换暂存目录中的数据库。连接先关闭，再复制主文件；原目录、已校验备份及发布回执继续遵守[共享运行环境决策](../architecture/2026-09-08-shared-runtime.md)。

复制完整源结构使旧项目 JSON 的导入标记不会被目标空库提前消费，后端 Provider 能在事务中导入项目并建立笔记与项目的同步版本。非空或含未知结构、状态的目标仍然拒绝自动合并。此例外只适用于已初始化同步结构的目标；旧格式目标即使笔记表为空，也可能在外部 JSON 中持有项目，不能据此替换。现状契约归属[正式运行环境](../../../../docs/runtime.md#导入仓库中的旧数据)。

## Alternatives considered

**捕获迁移异常后继续使用正式目录。** 会让旧笔记在启动后的工作区不可见，且并未解决导入失败，因此不采用。

**移除同步库合并保护。** 逐行拼接无法保持已有绑定、版本及冲突历史，因此只允许完整库迁入可证明为空的目标。

## Consequences

[回归测试](../../../../tests/contract/migration.test.ts)覆盖旧库迁入空同步库、启动升级后的项目与笔记版本、回收站与检索、完整同步绑定迁入，以及绑定、历史、会话偏好、删除项目和未知状态阻止替换。迁移仍保留双方原目录和可校验备份，不自动清理失败暂存目录。
