# Agent Note: 选择笔记不再触发全局禁用闪烁

Status: implemented

## Problem

在笔记列表中每次点选一条笔记，整个应用界面的按钮会同时变暗再恢复，随后列表头部还会闪出"加载中…"。闪烁的原因是 [NotebookApp](../../../../packages/ui-notes/src/client/components/notebook-app.tsx) 的 `openNote` 在取回笔记的 RPC 期间切换全局 `busy` 状态，而全应用每个按钮都以 `disabled={busy}` 传给 [ui-kit](../../../../packages/ui-kit/styles/components.css)，`.nui-btn:disabled` 的 `opacity: 0.55` 让侧边栏、笔记卡片和编辑器工具栏在请求往返期间整体进入禁用样式。`busy` 本是串行化写操作（新建、置顶、回收、移动、删除）的重入保护，把它复用在只读的选择请求上，代价是每次选择都让全界面禁用一次。

"加载中…"的来源是另一条链：[Autosave](../../../../packages/ui-notes/src/client/lib/autosave.ts) 的 `drain` 即使在没有未保存内容时也会发出 `changed('saved')`，NoteEditor 借此调用 `onSaved`，后者 `setRefresh` 让笔记列表与项目列表整体重拉，列表加载指示随每次纯切换闪现。

## Decision

点选笔记不再切换全局 `busy`。选择请求改用独立的 `AbortController`（沿用同文件 sync 效果的 signal 守卫模式）：新一次点选取消上一次未完成的选择，迟到的响应经 `signal.aborted` 守卫丢弃，连续快速点击按最后一次为准。其余会改变选中项的路径——切换列表视图（`view`）、新建笔记、深链打开（`openHash`）、删除项目——在改写选中项前取消在途选择请求，防止旧响应覆盖新状态。

全局 `busy` 保留原有职责：仅覆盖写操作期间的重入保护与按钮禁用，选择笔记期间按钮保持可用，编辑器输入也不会再随选择闪动。

`drain` 只在本次 flush 真正执行过保存时才发出 `changed('saved')`：入口处记录 `wasDirty`，无脏内容直接返回成功且不发事件。真实的编辑保存（含输入暂停后的自动保存、输入法结束、恢复草稿）仍照常通知，列表重排序行为不变。

## Alternatives considered

保留 `busy` 但用样式区分（如选择期间不再降不透明度）会破坏"禁用即视觉禁用"的既有约定，写操作进行中界面仍会闪动，问题没有消除。

在 `onSaved` 里按"内容是否真的变化"过滤刷新事件，需要比对保存前后的输入；把静默语义放进 `Autosave` 的事件边界更直接，也让所有调用方受益。

为选择单独引入一个只禁用笔记卡片的局部状态，仍会让列表区域闪动，且需要区分"哪块界面该禁用"的第三种语义；独立于 `busy` 的请求级取消守卫更简单，也不引入新的 UI 状态。

去掉 `busy` 改为完全并发（写操作不再互斥）能去掉闪烁，但会放开真正的并发风险，例如保存与回收竞争修订号；本次只缩小 `busy` 的覆盖面，不改变写操作的串行语义。

## Validation

[类型检查](../../../../package.json)（`tsc -b` 与 desktop 工程）通过；契约与桌面单测共 112 项通过、1 项按平台跳过，两轮修复后复跑结果一致。客户端构建（`build-client`）随单测运行完成。[autosave 契约测试](../../../../tests/integration/notes/rpc.test.ts)只断言布尔返回值与 note 状态，回调为空操作，`drain` 的事件收紧不与其冲突。仓库内没有针对 NotebookApp 选择行为的组件级测试，闪烁与加载指示属于视觉回归，现有测试基建（ui-kit e2e fixture）不覆盖该场景，按仓库"与风险成比例"的验证约定未新增测试。

## Consequences

点选笔记期间界面不再整体禁用；连续快速点击多条笔记时最后一条胜出，未完成的请求被取消。未编辑内容的切换不再发出任何保存通知、不再重拉列表，纯切换只剩一次取回目标笔记的请求；真实保存后的列表重排序与加载指示保持原样。慢网络下选择请求仍可能延迟，卡片不呈现忙碌态，但编辑器由选中结果驱动，不会展示错误内容。若未来选择请求需要承载写语义（如恢复回收站笔记），应回到 `busy` 串行保护，而不是复用本次的选择通道。
