# Agent Note: 同库同步数据代次与可恢复迁移

Status: implemented

## Problem

同步历史以内容哈希和父版本组成不可变图。折叠展示不解除同步引用，直接删旧版本会让现有设备缺少祖先；只覆盖服务器当前内容又会被客户端判定为历史回退。用户要求继续使用同一服务器库，并让未来其他不兼容的数据重写复用接入机制。

## Decision

采用独立于普通索引代数的数据代次和本地注册的迁移策略。迁移清单记录精确来源索引、完整候选基线及策略身份，不携带可执行代码。不可变对象先暂存并校验，再以一次 CAS 发布新代次；格式 2 阻止旧客户端继续向新基线写入。客户端预检跨越的迁移链，逐代备份并事务切换，保留离线分支及浏览器草稿的旧基线恢复路径。

历史精简作为 `history-rewrite@1` 策略，重写父引用并通过业务处理器显式映射跨记录版本引用；未知引用语义保守保留。选择范围复用界面阶段聚合函数，避免维护脚本复制折叠规则。协议与发布约束归属[同步契约](../../../../packages/feature-sync/README.md#数据代次)。传输优化和版本生成策略见[历史包决策](../bug-fix/2026-09-11-sync-history-packs.md)。

## Alternatives considered

直接删除折叠版本会破坏父引用及跨记录来源引用，无法作为安全精简。

创建独立服务器库并要求设备手动清理重接能够隔离历史，但改变用户的连接与使用流程，也没有解决后续不兼容迁移的通用问题。

把精简结果作为普通索引覆盖，缺少旧设备写入隔离和本地基线迁移依据，可能回灌历史或丢失离线编辑。

## Consequences

发布代次需要所有设备具备对应迁移实现。服务器保持普通 WebDAV，无需增加服务端业务 API。备份、本地压缩归档及远端旧对象保留，精简减少活动历史与正常传输成本，不立即回收全部磁盘空间。

契约测试覆盖同库迁移、多代跳转、未来策略注册、离线编辑、晚到草稿、并发发布、响应丢失、取消、损坏清单、备份失败和投影事务回滚。真实 HTTP 集成覆盖笔记来源引用、搜索投影及多设备内容收敛，也验证跨代次重试已保存请求保持幂等；真实数据快照核对当前笔记内容和精简数量。
