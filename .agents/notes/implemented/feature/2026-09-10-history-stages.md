# Agent Note: 笔记历史按编辑阶段展示

Status: implemented

## Problem

自动保存保护输入，但把每次短暂停顿产生的快照都列在历史主列表，会让一次写作淹没真正有用的恢复节点。降低保存频率会扩大丢失输入的窗口；删除中间版本则会影响同步版本链及合并重放。

## Decision

自动保存和底层版本保持完整，展示层使用可展开的编辑阶段。阶段边界、分页及恢复标记的唯一契约位于[同步契约](../../../../packages/feature-sync/README.md#自动合并与笔记历史)。本决策补充[自动合并与历史](2026-09-10-automatic-sync-merge.md)，不改变笔记正文 schema、父版本链或合并算法。

[分组逻辑](../../../../packages/ui-notes/src/client/lib/note-history.ts)仅消费 Capability 的版本关系和分类，不读取正文或同步存储。父子关系和完整图中的分支点约束聚合，时间仅判断连续编辑的间隔。加载更早页面后重新聚合，阶段以最新版本作为稳定标识，保留展开状态和选中的原始版本。

历史恢复需要可靠的操作身份。Provider 在原事务中创建独立的同步标记，无业务投影，注册生命周期由副本存储负责。它可跨设备传播，又不把展示元数据加入正文的合并字段。旧历史不猜测恢复意图，缺少标记的版本保留可访问性。

## Alternatives considered

**延长自动保存间隔。** 会削弱输入保护，而且不能解决同步合并产生的历史噪声。

**直接清理或压缩中间快照。** 涉及跨设备祖先关系、备份与离线合并，超出展示聚合的范围。

**只按时间聚合。** 会把不同分支或恢复操作混在一起，设备时钟变化也可能造成错误归组。

**本机保存恢复标记。** 另一台设备和完整重建后的历史无法识别恢复节点，因此采用已有通用同步类型机制。

## Validation

[分组契约测试](../../../../tests/contract/note-history.test.ts)覆盖分页边界、重复输入、五分钟间隔、时钟倒退和分支隔离。[自动合并测试](../../../../tests/contract/auto-merge.test.ts)及 [HTTP 集成](../../../../tests/integration/webdav-sync.test.ts)覆盖恢复标记的幂等、同步和重启。[浏览器验收](../../../../scripts/verify/notebook-smoke.mjs)覆盖默认聚合、展开原始保存、选择恢复和恢复节点展示，并供打包 Profile 使用。

## Consequences

历史主列表更紧凑，每次原始保存仍可恢复。按需分页可能让最后一个阶段的保存次数暂时不完整，界面明确提示加载后补全。底层容量增长仍需独立设计，当前不进行历史清理。恢复标记增加少量同步记录，旧客户端可保留它们，但不能据此显示恢复分类。
