# Agent Note: 自动同步合并与笔记历史

Status: implemented

## Problem

个人多设备使用不应要求用户理解并发分支或手动选择版本。即使自动合并不完全符合原意，保留可查看、可恢复的原始历史也比中断编辑更符合产品目标。后台合并还需要覆盖旧基线的自动保存，否则用户仍会在输入时遇到 revision 冲突。

## Decision

使用固定版本 Automerge，通过专用 Adapter 和 Worker 重放现有记录图。业务快照及原始父关系保持为事实来源，合并生成引用全部头的新版本；原始分支及合并前恢复记录持续保留。协议与体验的唯一说明位于[同步契约](../../../../packages/feature-sync/README.md)，转换和缓存细节位于[合并 Adapter](../../../../packages/adapter-merge-automerge/README.md)。本决策扩展[通用同步](2026-09-08-note-online-sync.md)，不改变 WebDAV 条件发布模型。

Actor、转换时间和遍历顺序确定化；相同内容的 Automerge 二进制不保证字节一致，因此只用作 Worker 内可丢弃缓存。历史列表读取原始记录，按[编辑阶段展示决策](2026-09-10-history-stages.md)聚合，恢复是新的业务写入，不回退同步头。

保存响应区分当前合并笔记与提交输入版本，持续输入沿自己的分支提交，避免把尚未展示的远端内容误删。请求回执与版本在同一 SQLite 事务保存，指纹仅保存 SHA-256，不重复存储正文。旧基线草稿与响应丢失重试使用同一条保存路径。

## Alternatives considered

**三方 diff 加人工处理。** diff3 仍会输出重叠冲突块，无法满足完全不出现人工冲突界面的要求。

**按设备时间整条覆盖。** 会丢失不重叠字段和正文的并行修改，也会受到设备时钟影响。

**AI 合并。** 增加网络、费用及输出不确定性；本地确定性合并和历史恢复已经满足需求。

**直接把 CRDT 二进制作为远端身份。** 相同业务结果可以得到不同序列化字节，容易产生重复合并版本；还会要求迁移现有历史格式。

## Validation

[自动合并测试](../../../../tests/integration/sync/auto-merge.test.ts)覆盖同位置文本、晚到分支、三个副本收敛、重启恢复、删除与编辑、响应丢失、提交前头变化、备份失败和连续输入。现有[同步契约测试](../../../../tests/integration/sync/sync.test.ts)保留未知类型、格式及对象完整性覆盖。[HTTP 集成](../../../../tests/integration/sync/webdav-sync.test.ts)检查真实 WebDAV 下无副本的笔记收敛及历史保留。[浏览器验收](../../../../tests/helpers/scenarios/notebook.mjs)检查双窗口编辑、历史展示和恢复，供链接与打包 Profile 共用。

## Consequences

原始版本无需重写，开启与关闭同步均保留本地历史。自动合并提供一致结果，不能保证人类语意或 Markdown 排版完全符合预期。冷重放成本随历史规模增长，缓存与 Worker 将其隔离到后台；历史不自动清理。未知类型仍需自己的合并策略。所有设备升级后获得完整体验，旧版保存客户端的返回 DTO 不与新界面混用。
