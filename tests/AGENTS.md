# 测试组织与执行规则

验收证据原则归属 [根规则](../AGENTS.md)。这里的集中式结构是本项目选定的 convention。

## 归属与发现

用例按测试范围组织：`unit/<module>/` 验证单模块行为；`component/<module>/` 独立挂载组件；`integration/<module>/` 验证真实模块、存储、协议或进程协作；`e2e/<feature>/` 经公开入口验证完整流程。desktop、sync-server 是层级下的子系统；独立安装和桌面交付归入 `e2e/distribution/`。跨范围文件拆分；使用浏览器本身不决定层级。不得新增含义不明的 contract 收纳目录。

[调度器](../scripts/test/run.mjs) 递归发现 `*.test.ts`、`*.test.tsx`、`*.test.js`、`*.test.mjs` 和 `test_*.py`。新增嵌套用例无需注册逐文件白名单。Python 由调度器直接执行；仅转调 Python 的 Node 包装测试不保留，真正的跨语言集成测试可以保留。

共享辅助设施放入 `helpers/runtime/`（安装、启动、就绪、认证准备和清理）、`helpers/browser/`（浏览器操作）、`helpers/services/`（测试服务）、`helpers/scenarios/`（跨环境验收流程）；固定样本、测试页面和随包运行的探针放入 `fixtures/<module>/`。helpers 与 fixtures 不参与发现。仅一个用例使用的辅助代码就近保留；截图、日志和临时数据写入 `.pack/` 或测试专属临时目录。

## 独立性与资源

- 用例独立准备前置数据，不依赖其他测试的顺序、账号配置或残留数据。完整流程内可以有顺序步骤；失败的步骤不得继续产生通过报告。
- 环境辅助函数只准备环境，返回地址和必要操作句柄，不默认执行笔记、任务或 Safe UI。认证准备与认证正确性断言分离。
- 每项资源有明确所有者；注册进程、浏览器、服务、监听器和定时器的同时安排失败与正常路径的清理。清理完成后才报告结束；验证关闭行为时实际重新绑定端口。
- 用例只操作自己创建的可丢弃数据。遵守根规则中的 DSH_HOME 隔离和用户数据备份要求。
- 安装验收从目标安装目录解析被测模块，原生探针由随包运行时执行。仓库可以提供测试工具，不能提供替代被测安装产物的实现。
- 源码、干净安装、桌面和 Windows 启动由显式入口复用场景。同环境的等价用例合并，跨环境覆盖保留。

## 环境与结果

命令语义统一维护在 [开发文档](../docs/development.md#verification)，命令实现以 [package scripts](../package.json) 为准。普通组排除 `distribution/`、`docker/`、`linux/` 环境目录；`posix/` 在 Windows 不适用。Docker/Compose、Linux 容器、macOS arm64 和 Windows 验收通过独立执行组选择，不由普通测试隐式触发。

显式平台验收缺少平台、Python、浏览器、Docker 或安装产物等必需前置条件时失败并说明原因。平台不适用应明确报告；空组不能成功。`--prepared` 只供本次已完成构建/打包及 Profile 准备的聚合或定位运行使用；公共命令默认自行准备。`--match` 选择路径，`--list` 只列出发现结果。保留现有截图变量、失败现场和 `--skip-package` 行为。

结果必须区分已通过、失败和未执行的平台。未在对应系统与架构验证的交付不得报告为通过。失败退出码必须传到公共命令与 CI。
