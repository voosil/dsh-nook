# Agent Note: 通用任务与想法提炼闭环

Status: implemented

## Problem

笔记承接了观察与想法，但从混乱来源到明确计划仍占用用户大量决策带宽。对话交办、个人日程和 Agent 执行缺少共享的持久状态，无法可靠表达等待、已授权、已执行和已验收，也无法把执行结果反馈到后续理解。

## Decision

采用来源理解、版本提案、计划任务、执行验收四层结构，行为归属[任务指南](../../../docs/tasks.md)。UI、DSH 工具和本地 MCP 共用业务能力，DSH 会话与调度解耦，执行以明确产物回报为准。三种模型角色显式配置，固定要求与实际产物版本贯穿验收；计划整体接受，原范围缺陷最多两轮自动返工。

单主机裁决与版本化请求回执组合，避免异步同步被误认为操作已生效。同步存储通过条件创建确认不可轮换的主机归属，弥补两台设备尚未交换设置时的竞争窗口。领取、提交和回执与任务投影使用同一副本事务。无法确认的中断执行需介入，保留重复执行风险的判断权。

理解基线只在成功提交后推进，来源与提案在批准时再次检查版本。完成任务形成确定身份的派生复盘记录，处理成功后不因重启重复提炼。模型推导与用户表达分开记录，既有批准和暂缓信息作为后续推理输入。

## Alternatives considered

**每次保存重读全部笔记。** 连续编辑会产生重复推理，仍难处理删除和撤回；成功基线、静默窗口和变更上下文能够表达增量。

**把官方会话提醒当作全局调度器。** 会话生命周期与日历重复规则不承担业务运行和恢复语义，使用独立持久调度器并通过公开 DSH Adapter 启动执行。

**依靠最终一致的设置字段选主。** 首次并发启用可能各自进入执行；同步存储上的原子归属确认阻止这一窗口。首版不轮换归属，主机重启且无法访问同步存储时等待确认。

**只凭执行者总结或空闲状态验收。** 无法证明产品要求和实际产物一致，因此要求结构化证据、独立验收上下文以及产物版本核验。

## Consequences

用户需要在执行主机配置模型角色和工作目录，任务页显示简短可行动事项。外部 Agent 仍需遵循领取与心跳协议，撤销领取不能物理停止不受 Nook 管理的进程。主机身份文件不能用于迁移或复制，产物本地路径不等于跨设备附件。

验证使用临时目录或开发 Profile，覆盖契约、SQLite 副本同步、真实 Gateway 与 MCP 桥、主机条件写竞争、后台保留生命周期及浏览器任务流程。验证记录随本主题更新。模拟模型测试证明状态与边界，不替代真实模型的产品判断质量评估。

## Validation

最终契约、桌面和集成回归为 141 项通过，3 项 Windows 专项按平台跳过；4 项浏览器回归通过，覆盖完整 Profile、Safe UI、开发热更新和控件交互。任务验收包含真实 Gateway、MCP stdio 握手与工具调用、SQLite 同步和条件写竞争；执行 Adapter 测试核验明确回报、持久恢复与产物变化拒绝。类型、构建、格式、文档、包边界、样式和 peer 门禁通过，50 个包的干净安装与 33 项 Profile 组成通过浏览器闭环验证。

真实模型的规划与验收质量、原生系统通知交互以及设备实际休眠唤醒尚未完成人工实机验收；自动测试覆盖恢复时间策略、后台保留和执行中断。所有验证数据使用临时目录或开发 Profile，不读取正式 DSH home。
