# Agent Note: 独立同步指南与 Linux 一键配置

Status: implemented

## Problem

用户需要把服务器和 NAS 的长篇指南从配置弹窗移到专门页面，并希望只执行一行命令便完成 Linux 服务器配置，明确得到要填入 Nook 的连接信息。工具必须支持用户选择内网／VPN、无域名公网 IP 和有公网域名三种环境。

## Decision

指南使用独立的 `#nook-sync-guide` 路由，弹窗只显示入口，返回时保留未提交的字段。一行命令内嵌本版本安装脚本，同时提供可审阅的脚本下载，避免尚未发布的 URL 或默认分支更新改变正在部署的内容。

部署使用发行版 Apache 二进制、独立配置和 systemd 单元，串行处理 WebDAV 请求。域名模式调用 Certbot 自动申请和续期；内网与 IP 模式生成独立 CA。Nook 增加连接专用 CA 字段，由 HTTP Adapter 传入 Node TLS 校验，保留证书链、有效期和地址验证，不改变系统信任。

工具在权限、连接和条件写入检查通过后输出 URL、用户名、随机密码及 CA；保留安装回执以支持失败重试，并拒绝接管不明目录或更换已有部署的目标。具体支持条件和运维规则由[部署工具说明](../../../scripts/sync-server/README.md)承载，业务协议由[同步决策](2026-09-08-note-online-sync.md)承载。

容器入口复用同一 Apache、证书和探测函数，以数据卷锁维持单写入者。指南交付固定版本的完整部署包，容器默认从 GHCR 拉取；无 Docker 用户保留系统安装入口。连接文件导入只填充表单，用户核对地址后通过既有 Host 配置流程验证并开启同步，避免把导入文件变成隐式联网操作。部署契约由 [Docker 说明](../../../scripts/sync-server/DOCKER.md)承载，发布方式见[镜像发布决策](2026-09-09-sync-container-release.md)。

## Alternatives considered

**继续把指南写在弹窗内。** 用户明确要求专门页面，因此配置弹窗只保留入口，部署步骤拥有独立可返回的地址。

**仅支持公网域名。** 用户要求三种网络环境；内网设备不能依赖公网 ACME 验证，无域名 IP 也不应被迫购买域名。

**关闭 TLS 校验或安装系统级 CA。** 前者失去服务器身份验证，后者增加跨设备管理步骤和信任范围。选择只对 Nook 当前同步连接信任工具产生的 CA。

**强制所有用户安装 Docker。** Docker 作为已有容器环境的优先入口，系统安装工具继续服务无 Docker 用户；两者复用服务配置，避免行为分叉。

**只把脚本包装成 CLI。** 它不能消除逐项复制连接信息的负担；可导入文件统一携带地址、凭据和 CA，同时保留手动配置。

## Validation

类型检查和构建验证 Host／Client 字段一致；契约测试验证一行命令解压后与可下载源代码一致，并执行参数、权限和备份保护测试。真实 HTTPS 集成验证缺少 CA 或地址不匹配时在发送凭据前拒绝连接，信任不会影响其他连接。

Linux 隔离验收范围和模拟边界见部署工具说明。完整安装包浏览器验收检查弹窗仅有入口、独立页面路由、一行命令、返回后表单保留及窄窗口布局。

已通过 48 项契约及桌面测试、18 项集成测试；Debian 12 容器内三种模式均通过真实 Apache 验收，并以实际 Nook Adapter 完成两个副本的并发冲突与收敛检查。35 个干净安装包和 25 个 Profile 组合项通过验收。截图检查修复了指南正文误继承侧栏字号的问题。

开发模式验收在全新临时目录中准备桌面运行时两次超时，因此测试复用打包器已校验的 Node 缓存；仍执行真实打包、启动和重载，避免把重复下载的网络耗时计入启动窗口。复验通过，连同普通 Profile 与 Safe UI，三个端到端用例均通过。

容器验收覆盖真实 Compose 启停、并发卷锁、容器重建、证书备份替换、目标变更拒绝及导出权限，并使用实际 Nook Adapter 验证双副本冲突收敛。导入契约测试覆盖版本兼容、畸形与超限输入；浏览器验收覆盖失败后保留表单、导入不联网以及验证开启同步。

家庭服务器的默认入口和文本交接由[安装助手决策](2026-09-09-sync-assistant.md)承载；本笔记保留其他网络环境的系统安装与文件导入依据。

## Consequences

三种环境都能使用 HTTPS，无需用户设置 Nook 环境变量。私有 CA 需要复制一次到每台设备；公网 IP 模式不承诺浏览器默认信任。自动化无法代替用户控制的 DNS、安全组及 VPN 网络配置；失败不会输出虚假的配置成功结果。
