# Agent Note: 同步传输吞吐与发现延迟

Status: implemented

## Problem

小体积笔记的历史包含大量独立对象。逐个等待请求、重复建立连接以及上传后的完整回读使网络往返成本随版本数量累计；接收设备的检查间隔又增加了小修改的可见延迟。

此决策补充[通用同步](../feature/2026-09-08-note-online-sync.md)，不改变版本身份、索引格式或[自动合并](../feature/2026-09-10-automatic-sync-merge.md)语义。

## Decision

引擎采用有界并发，下载以记录为单位保留共享祖先的顺序遍历，上传在完整依赖集合验证成功后统一发布索引。共享附件和同轮竞争重试共用已验证对象，避免重复传输。批次失败先取消并等待全部任务结束，防止后台请求越过配置切换或卸载边界。

连接池归存储实例所有，Feature 在连接探测和每轮同步的结束路径释放它；各实例保留独立证书信任和取消域。接收端缩短检查间隔，同步期间留下的本地待发版本优先调度下一轮。精确参数、清理接口和限制由[同步契约](../../../packages/feature-sync/README.md)承载。

## Alternatives considered

无限并发会令大历史同时持有大量正文、文件和连接，并增加服务端压力；采用固定上限，使内存和请求数量受控。

省略上传回读可以进一步减少请求，但削弱不兼容 WebDAV 和错误存储内容的发现能力，因此保留完整字节校验。

服务器推送适合及时通知在线设备，但通用 WebDAV 没有本协议所需的订阅接口。它需要配套服务端、订阅鉴权、重连与漏通知补偿；本变更保留可替换存储边界及轮询，不引入专用服务依赖。

历史压缩或批量对象格式需要兼容协议及恢复设计；后续的[版本生成与历史包决策](2026-09-11-sync-history-packs.md)在保留全部原始对象的条件下补充传输侧历史包。

## Validation

[同步契约测试](../../../tests/contract/sync.test.ts)通过模拟每次请求的网络延迟验证有界并发、共享附件去重、索引竞争重试复用、完整历史收敛，以及上传校验失败和下载取消后的批次隔离。[WebDAV 集成测试](../../../tests/integration/webdav-sync.test.ts)验证真实连接复用、连接上限和关闭后的请求拒绝，保留私有 CA 隔离与独立 Apache 兼容验收。

本次以原仓库版本叠加同步改动的临时源码快照完成全量类型检查与构建，避免将同期 UI 包的未完成类型改动纳入验收。契约、桌面和集成测试共 106 项通过、3 项按平台跳过；同步导入测试使用规范化临时目录重跑通过，排除 macOS 路径别名差异。[Profile 验证](../../../scripts/verify/verify-profile.mjs)和[干净安装包验收](../../../scripts/verify/verify-package.mjs)通过，覆盖 36 个打包包及实际运行时。模拟 10 ms 请求延迟的 54 版本上传约 310 ms，串行请求的等待下限为 1,100 ms；此结果不代表公网端到端耗时。

## Consequences

多记录或批量上传能够重叠网络等待，完整校验和条件索引发布仍约束最终确认。不含历史包的旧索引仍依赖逐层发现父版本；轮询不是实时推送，更频繁的检查也增加空闲时索引读取和本地对账次数。
