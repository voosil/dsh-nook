# Agent Note: 面向 Agent 编码的文档收录边界

Status: implemented

## Problem

功能介绍和源码已表达的事实进入通用编码文档，会增加 Agent 的阅读与维护成本。把所有外部接入细节集中到 discovery，也会使每次开发需要读取与当前任务无关的信息。仅按文件大小拆分无法消除这些冗余。

## Decision

[文档标准](../../../docs/AGENTS.md)以指导 Agent 编码为收录目的。`docs/` 只承载规范、约束、横切机制和核心技术现状；功能现状从源码和测试检索，历史取舍从已有决策笔记检索。包及工具文档只补充非显然契约，不承接被删去的产品手册。DSH discovery 限定为共享基线，局部接入事实和未知项随所属包维护。

任务功能导览、同步配置导览和应用更新操作说明不单独维护。同步代次发布的副作用、部署助手的发布校验与恢复边界保留在所属模块；运行快照切换、进程和数据保护边界保留在核心技术文档。源码已明确表达的 API 与配置清单不抄写。

## Alternatives considered

仅压缩句子或限制行数：不能改变所有功能事实集中追加的规则，长段落也能绕过行数限制。

按章节拆成 discovery 子目录，或把产品说明整篇搬到包 README：缩短入口但保留了全部冗余，形成与源码并行的第二套功能描述。

把跨包功能认定为横切技术主题：功能包拆分方式不能证明其说明对其他模块编码有价值，仍会让 `docs/` 随功能数增长。

## Consequences

Agent 按任务读取相关规则、代码、测试和决策笔记，无需先读完整产品说明。文档门禁检查引用与格式，内容是否影响编码判断仍需审查。本文档整理不改变运行时行为，也不更改既有功能决策。
