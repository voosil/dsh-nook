# Agent Note: 网页与桌面共用正式数据和后端

Status: implemented

## Problem

同一产品的日常网页入口和桌面入口各自启动后端并选择不同的数据目录，使已有笔记无法跨入口读取。只统一数据库路径会触发互斥锁，也无法解决两个进程的项目文件写入与生命周期归属。

## Decision

[正式运行环境](../../../docs/runtime.md)把数据位置与前端入口分开。先启动的入口提供标准 Node 和离线 seed，独立 broker 拥有共享后端；后启动的入口连接已有 broker。浏览器和 Electron 保留原有 DSH 鉴权及 Nook RPC，不增加业务 API 或跨 Host/Client 的非 JSON 对象。

broker 使用仅当前用户可访问的 Unix socket 传递启动 URL、日志和连接释放消息。短路径由正式根目录的指纹派生，避免 macOS 的 socket 路径长度限制。标准 Node 的原生文件锁决定唯一 broker，进程退出由内核释放锁；取得锁的进程才能清理自己的旧 socket。数据备份锁继续由 DSH 监督进程持有。

broker 的私有文件使用限制性 umask。macOS 复制符号链接时，其 inode 权限随 umask 改变，不能作为运行时完整性的稳定依据；清单对链接记录目标字符串，对普通文件和目录保留实际执行权限检查，并继续拒绝越界链接。限制性 umask 下的复制与校验由[运行时安装回归测试](../../../tests/desktop/payload.test.ts)覆盖。

每个入口持有独立连接。普通退出释放该连接；入口崩溃也会关闭 socket。最后一个连接结束才停止后端，因此首次启动它的入口退出不会影响其他入口。broker 与 DSH 之间保留独立监督进程的 IPC，broker 退出也触发进程组清理。目录安装及服务启动可取消，最后一次释放等待后端退出。

迁移库只操作已核实的 Nook 自有格式。它保存源、目标和合并结果的可校验快照，按 ID 合并笔记和项目，在同文件系统以保留旧目录的方式发布。相同标识但内容不同的记录停止迁移，不推测哪份更新；普通文件冲突同样停止。准备与完成回执使中断后的目录切换可检查、可继续，不自动重放已经完成的导入。

旧 Harness home 的会话、凭据与 Profile 配置没有通用的合并契约，因此不自动合并。用户原始目录保留，正式入口之后共享桌面 home 的配置。这一边界避免以笔记迁移冒充完整 DSH home 迁移。

## Alternatives considered

**只修改 DSH_HOME 或建立数据软链接。** 数据锁仍会拒绝第二个后端；绕过锁则让多个进程竞争项目 JSON 和其他非数据库文件，不满足并行使用。

**第一个前端直接拥有后端。** 该前端退出会断开另一端。独立 broker 按实际连接数管理生命周期，使所有入口地位相同。

**常驻系统服务或开机启动项。** 会增加安装和系统配置范围。按入口连接存续的用户进程已能满足本机使用，不增加 LaunchAgent。

**覆盖式复制旧网页目录。** 会覆盖桌面已有笔记，且无法判断冲突。选择预先备份、可检查合并及保留两个原目录。

## Consequences

创建新后端需要准备或校验运行时快照，加入现有后端只建立连接。当前后端版本和端口优先，更新代码、配置或端口需要关闭所有正式入口再启动。两个前端的页面状态各自独立，数据共享不等于即时同步尚未保存的编辑。

[迁移测试](../../../tests/contract/migration.test.ts)覆盖双向数据保留、FTS、回收站、项目、冲突与中断继续。[共享生命周期测试](../../../tests/integration/shared-runtime.test.ts)覆盖竞争启动、单后端复用、独立退出和再次启动。[真实窗口验收](../../../scripts/verify-desktop.mjs)在搬移后的应用和真实浏览器中验证同一笔记及后端地址。[开发模式验收](../../../tests/e2e/dev-modes.test.ts)使用临时仓库及显式临时正式目录，避免触碰用户数据。
